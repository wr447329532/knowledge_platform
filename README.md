文件共享和知识管理平台
=================================

本项目是在 `vscode` 目录下从 0 开发的**文件共享和知识管理平台**，采用 **Python + FastAPI** 后端与 **Vue 3 + Vite** 前端。  
**最后更新：2026 年 3 月 20 日**

**当前已实现：**

- 用户系统：**邮箱登录**、管理员创建用户（邮箱必填，用户名仅用于显示）、强密码策略（8 位以上，含大小写、数字、特殊字符）
- 文件库：创建 / 编辑 / 删除 / 软删除（回收站），按文件库管理文件；支持**部门库**（所属部门成员可访问）
- 文件上传 / 下载 / 版本历史 / 重命名 / **回收站**（已删除的文件库与文件统一列表展示，恢复、彻底删除，超过 30 天自动清理）
- 文件版本历史已支持显示上传者（版本号、大小、上传者、上传时间）
- **版本匹配上传**：上传前自动提取关键词并搜索库内可能相关文件；有结果时在上传弹窗内进行版本确认（作为新版本或新文件），无结果直接上传；支持多文件队列逐一确认
- 在线预览：点击文件名在新窗口预览，支持图片、PDF、文本（txt/md/json 等）
- **部门管理**：部门树、部门库、新建子部门、负责人展示、部门搜索
- **共享文件库**：基于库级 ACL 的「我分享的文件库 / 分享给我的文件库」视图，统一展示库名称、共享范围（公开/部门/指定成员）、我的权限（读写/只读）
- **共享文件（单文件）**：后端接口保留；前端“单文件分享”按钮已先行隐藏（后续成熟后再评估重新开放）
- **我的文件库**：列表与网格视图、排序（最近修改/文件名/大小/创建时间）、三点操作菜单、长文件名省略
- **统一权限模型（库级 ACL）**：
  - 访问优先级：超级管理员 › 库拥有者 › 库成员 › 部门库成员 › 公开库
  - `Library.visibility = private / members / department / public` 控制库可见范围
  - `LibraryMember` 维护库成员及角色（只读 / 读写）；`allow_download` 控制非拥有者是否可下载
  - 后端 `has_library_access / can_access_file / can_download_file / get_accessible_library_ids` 统一判定访问与下载权限
  - 高管（`executive`）默认可预览、可下载（前提是对文件具备访问权限）
  - 修复了「无部门用户误看到全部部门库」的权限漏洞（无部门或无效部门的普通用户不再拥有全局访问）
- **账户管理（普通用户）**：
  - 右上角用户头像下拉菜单进入账户设置、系统管理（仅管理员）、部门管理（仅部门负责人）、退出登录；侧边栏不再保留账户/系统管理入口
  - 个人信息：显示并支持修改姓名，邮箱和所属部门只读（由管理员维护），保存后即时生效并有成功提示
  - 安全设置：支持修改密码（校验原密码 + 强密码规则），并可查看动态安全信息（账户状态、上次登录时间、上次修改密码时间）
- 审计日志：记录上传、删除、恢复、分享、预览、下载等操作，支持按用户与操作类型模糊筛选（仅管理员可查）；支持**导出日志**为 Excel 下载到本地
- 系统管理：
  - **用户管理**：启用/停用、重置密码、分配部门、管理员标记
  - **部门管理**：树形表格、存储统计占位、部门负责人
  - **存储管理（新）**：按部门 / 用户 / 文件类型聚合存储使用，支持配额调整
  - **通知管理（新）**：通知模板、发送历史、通知开关、管理员一键群发通知

**后续规划：** 新建资料库更细粒度权限设置（角色 / 继承策略）、全文搜索、本地 LLM 知识问答等。

### 功能完善建议（补充路线图）

在当前“文件共享 + 部门协作 + 审计/通知/回收站”基础上，功能侧建议优先补齐以下能力，以提升日常可用性与协作效率。

#### P0（会直接影响日常协作与可用性）

- **更完整的文件夹能力**
  - 目前已有：创建目录、重命名、删除（非空目录会拒绝）
  - 建议补齐：
    - 移动/复制（含跨目录）
    - 批量操作：批量下载/删除/移动/恢复
    - 目录打包下载（zip）
    - 更好的目录导航（面包屑、树形展开、快捷定位）

- **搜索能力升级**
  - 目前：库内按路径模糊匹配（文件名/路径）
  - 建议补齐：
    - 全局搜索（跨库，按权限过滤）
    - 多条件筛选：文件类型/时间范围/上传者/库范围
    - 中文分词与同义词（后续再演进到全文检索）

- **版本管理闭环**
  - 目前：版本历史列表、支持下载/预览指定版本（`version_no`）
  - 建议补齐：
    - 版本备注（comment）与展示上传者
    - 回滚到某版本（将指定版本内容写为新版本）
    - 删除历史版本（策略：至少保留 1 个版本，或禁止删除最新版本）
    - 版本保留策略（最多 N 个/保留 M 天）

- **受控预览性能（PDF 单页缓存建议）**
  - 背景：PDF 常见几百页，受控预览需“按页渲染为图片 + 加水印”，属于 CPU 密集操作
  - 建议：仅对 PDF 的“渲染页图”启用**磁盘缓存**（最小化实现即可），避免同一用户反复翻页/回看时重复渲染
  - 参考参数（可按服务器资源调整）：
    - 缓存键：`entry_id + version_no + page + user_email`（水印按邮箱，避免串用户）
    - 过期：TTL 7 天
    - 容量上限：5–10GB（超限删除最旧）

- **大文件与上传可靠性**
  - 目前：单文件 500MB 限制、上传进度条
  - 建议补齐：
    - 分片上传 + 断点续传 + 失败重试
    - Hash 校验（避免传输损坏），可选“秒传/去重”

#### P1（协作效率与权限表达增强）

- **权限的可解释性 / 可配置性**
  - 在库/文件列表中展示“权限来源”（公开/部门/被添加为成员/拥有者），减少“看得到但为什么不能操作”的困惑
  - 权限变更记录与通知（谁在何时给了谁读写）
  - 细粒度角色扩展：库管理员、仅上传不可删、仅可下载不可上传等（按实际需求取舍）

- **文件锁与冲突避免**
  - 手动/自动锁定、解锁权限、锁定状态提示，避免多人同时更新“终稿”导致版本混乱

- **分享能力增强**
  - 共享链接（可配置：过期时间/密码/下载次数/是否允许外部下载）
  - 分享撤销与访问统计（谁在何时访问/下载）

#### P2（知识管理属性增强：让它更像“知识平台”）

- **元数据与分类体系**
  - 标签/分类/项目/专业字段、密级/来源/作者等；支持按元数据筛选与统计

- **预览能力增强**
  - Office 在线预览（docx/xlsx/pptx）
  - Markdown 渲染、代码高亮、PDF 内搜索与目录

- **订阅与通知规则**
  - 订阅资料库/目录/关键词，有更新自动通知；可选每日/每周摘要

- **知识卡片/摘要与关联推荐（可选，后续阶段）**
  - 文件摘要、关键结论提取、相关文件推荐（可复用“版本匹配上传”的相似度思路）

#### 建议优先落地的 3 个功能（投入产出比最高）

- **文件夹：移动/复制 + 批量操作 + 目录打包下载**
- **搜索：全局搜索（按权限过滤）+ 多条件筛选**
- **版本：回滚 + 版本备注/上传者 + 保留策略**

| **体验** | 在版本历史中预览某版本 | 版本表格每行增加「预览」按钮，调用现有预览 API 并传 `version_no`，在新窗口打开该版本内容。 |
| **能力** | 恢复到此版本（回滚） | 新增接口或复用上传逻辑：将指定版本的文件内容写为「新版本」（version_no+1），实现「回滚」为当前内容；需校验当前用户有写权限。 |
| **能力** | 删除指定历史版本 | 新增 `DELETE /files/versions?entry_id=xx&version_no=yy`（仅允许删除非最新版本或由管理员/拥有者操作），并删除对应磁盘文件；注意至少保留一个版本。 |
| **策略** | 版本数量与保留策略 | 可选：单文件最多保留 N 个版本、或只保留最近 M 天；定时任务或在上传时清理超出的旧版本，避免存储无限增长。 |
| **上传** | 上传时可选「版本说明」 | `FileVersion` 已有 `comment` 字段；上传接口与上传弹窗支持可选填写「版本说明」，列表/版本历史中展示。 |

快速开始
--------

> ⚠️ **强制安全要求：必须修改 JWT_SECRET_KEY**
>
> 后端使用 JWT 进行身份认证，密钥由 `.env` 文件中的 `JWT_SECRET_KEY` 控制。  
> **如果保留默认值 `change_this_secret_in_env`，后端会在启动时直接报错退出，拒绝运行。**  
> 请在部署前务必：
> - 在项目根目录创建或修改 `.env` 文件；
> - 设置一个足够随机、长度较长的 `JWT_SECRET_KEY`（例如 32 位以上随机字符串）；
> - 重启后端服务。

**注意：需先启动后端，再启动前端，最后在浏览器打开前端地址。**

**1. 启动后端**

在项目根目录 `knowledge_platform` 下，使用已安装依赖的 Python 环境（如 conda）：

```bash
cd knowledge_platform
conda activate finance_agent   # 或你的环境，需已 pip install -r requirements.txt
uvicorn backend.app.main:app --reload --host 0.0.0.0
```

或使用脚本（会自动用 finance_agent 环境）：

```bash
cd knowledge_platform
./run_backend.sh
```

后端默认运行在：`http://127.0.0.1:8000`  
接口文档：`http://127.0.0.1:8000/docs`

**2. 启动前端**

新开一个终端：

```bash
cd knowledge_platform/frontend
npm install    # 首次需要
npm run dev
```

前端默认运行在：`http://localhost:5173`

**3. 登录**

浏览器打开 **http://localhost:5173**，使用默认管理员账号：

- 邮箱：`admin@example.com`（或数据库中为该账号配置的邮箱）
- 密码：`admin123`（首次使用建议通过系统管理修改为强密码）

**4. 常用地址**

- 前端页面：http://localhost:5173
- 后端健康检查：http://127.0.0.1:8000/health
- 接口文档（Swagger）：http://127.0.0.1:8000/docs
